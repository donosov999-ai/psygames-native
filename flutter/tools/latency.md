# Отклик и показ стимула — одной меркой для обеих версий

Прибор: `lib/shell/tap_latency.dart`. Включается флагами сборки и в обычной сборке
не существует (`bool.fromEnvironment`), поэтому в выпуск ничего не едет.

## Зачем

В таблице переезда (`FLUTTER_MIGRATION.md`) стоит «8,5 мс против 0,23 мс» с честной
оговоркой «стенды разные»: одно число снято в браузере, другое в widget-пробе.
Для проб на реакцию (раздел «Конфликт внимания») такая разница важна по существу:
там время реакции человека и есть результат, и задержка приложения уезжает прямо в него.

## Две величины

| Что | Flutter | Нынешняя версия в WebView |
|---|---|---|
| **ПОКАЗ**: от решения показать стимул до ближайшего кадра | `measureStimulusFrame` → `addPostFrameCallback` | разметка в экране игры → `requestAnimationFrame` |
| **ОТКЛИК**: от отметки времени касания до ближайшего кадра | `TapLatency` → `PointerDownEvent.timeStamp` → `currentSystemFrameTimeStamp` | `webTapLatencyJs` → `event.timeStamp` → `requestAnimationFrame` |

Обе версии считают разность ВНУТРИ себя и отдают готовое число: часы двух процессов
не сравниваются. Строки одинаковые (`ПОКАЗ …` / `ОТКЛИК …`), разбираются одним грепом.

## Как снять

```bash
# 1. Веб-часть внутрь приложения (нужна, чтобы обе версии жили на одном устройстве)
REBUILD=1 bash flutter/tools/embed-web.sh

# 2. Нативный экран: игра начинается сама, стимулы сменяются по окну ответа
flutter run -d <udid> \
  --dart-define=TAP_LATENCY=true --dart-define=AUTOSTART=true \
  --dart-define=START_ROUTE=/games/stroop

# 3. ТОТ ЖЕ экран в нынешней версии, на том же устройстве: перехват выключен
flutter run -d <udid> \
  --dart-define=TAP_LATENCY=true --dart-define=WEB_ONLY=true \
  --dart-define=START_ROUTE='/games/stroop?autostart=1'
```

Числа собираются из журнала прогона: `grep 'ПОКАЗ' <журнал>`.

## 🔴 ЧТО ПОКАЗАЛ ПЕРВЫЙ ЗАХОД: СРАВНИМОГО ЧИСЛА ПОКА НЕТ

Замер 23.09.2026, Струп, симулятор iPhone 17 Pro Max, оба прогона на одном устройстве.
Три способа, и каждый оказался НЕсимметричным — числа получились, сравнение нет.

| Способ | Flutter | Нынешняя версия | Почему негоден |
|---|---|---|---|
| Разность считает сама страница (`performance.now()`) | 17,6 мс (медиана, n=32) | 11 значений из 13 — ровно 0,00 | WebKit огрубляет часы страницы до 1 мс |
| Метки каналом, часы Dart, ОДИН кадровый колбэк | 17,6 мс | 0,35 мс (медиана, n=10) | `requestAnimationFrame` срабатывает ДО отрисовки, `addPostFrameCallback` — после построения |
| Метки каналом, ДВА кадровых колбэка | 33,5 мс (n=37) | 15,1 мс (n=18) | Flutter второй кадр запрашивает явно, браузер два колбэка склеивает в один кадр |

Вывод: писать «одна версия отзывчивее другой» по этим числам нельзя — это была бы та же
ошибка, что «8,5 мс против 0,23 мс», только с более аккуратным видом.

ЧТО НУЖНО ДЛЯ ЧЕСТНОГО ЧИСЛА: общий наблюдатель СНАРУЖИ обеих версий —
запись экрана телефона с частотой выше кадровой (или трассировка кадров в Instruments),
где видно, на каком кадре появился стимул и на каком отпечаталось касание. Пока этого нет,
в таблице переезда у строки отклика стоит прочерк, а не число.

## Чего этот прибор НЕ меряет

⚠️ **Касание в нативный слой из панели симулятора не доставляется** (замер 23.09.2026:
WebView на синтетические нажатия отвечает, Flutter — нет). Поэтому величина «ОТКЛИК»
на симуляторе снимается только у веб-версии, а у нативной остаётся неизмеренной.
Честный путь для неё — живой телефон и настоящий палец либо `flutter drive` на
устройстве; до этого писать «отклик Flutter такой-то» нельзя.

⚠️ Симулятор — не телефон: числа годятся для СРАВНЕНИЯ двух версий на одном железе,
а не как паспортные.
