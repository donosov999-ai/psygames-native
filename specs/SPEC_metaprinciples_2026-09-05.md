# PsyGames — три метарежима поверх всех игр: «Детализация + Вал», претест и уверенность, ночной цикл

Источник принципов: `NZT48_USKORENNOE_OBUCHENIE_v2_2_1.md` (18 принципов ускоренного обучения, верификация по литературе). Идея: не новые игры, а три режима над существующими 70, каждый цепляется за уже написанный сервис. ## 1. Режим «Детализация + Вал» (принцип 1, Шестов; interleaved practice, Rohrer 2012)

**Зачем.** Две фазы обучения дают разное: медленный разбор с подсказками строит понимание (префронтальная кора), непрерывный поток без пауз переводит навык в автоматизм (базальные ганглии). Сейчас в приложении обе фазы смешаны: человек играет с подсказками, останавливается, снова играет. Разделение фаз и есть приём, которого нет у Lumosity и Elevate.

**Как устроено — один плейлист-режим на любую игру или набор игр.**
- Фаза «Детализация», 5 минут: игра идёт с включёнными подсказками (`gameContextHelp`), разбором ошибки сразу после каждой (принцип 6), без таймера давления. Можно останавливаться.
- Фаза «Вал», 20 минут: те же игры подряд, подсказки выключены, разбор ошибок не показывается (только счёт), **кнопка паузы исчезает**, между играми нет экрана результата, следующая стартует через 1,5 с автоматически. Прервал — серия помечена как незавершённая.
- После Вала — один экран итога: разность метрик между фазами по каждой игре (скорость, точность). Это и есть замер: цена «работы без опоры».
- Длительности 5/20 — параметры плейлиста; для Алекса 3/8.

**За что цепляться.** Плейлисты уже есть: `services/warmup.ts` (`PlaylistStep`, `buildDayPlaylist`, `stepToParams` — параметры шага передаются игре строкой). Добавить в `PlaylistStep` поле `phase: 'detail' | 'flow'` и в `stepToParams` два флага: `hints=0/1`, `pause=0/1`, `autonext=1`. Пауза централизована в `services/gamePause.ts` (`holdGame`, `isGameHeld`) — во фазе flow `holdGame` возвращает no-op, а кнопка паузы в HUD скрывается по флагу. Одна сессия на весь режим по образцу `services/series.ts` (`SeriesRun` с массивом блоков, `series_complete`), чтобы разности считались внутри одного прогона.

**Метрика.** Для каждой игры: `flow_speed / detail_speed` и `flow_accuracy − detail_accuracy`. Рост отношения скорости при удержании точности неделя к неделе = автоматизация. Пишется в `sessionHistory` как одна запись с двумя фазами.

**Приёмка.** Проба: в фазе flow `isGameHeld()` не может стать true, экран результата между играми не показывается, суммарное время фазы 20 мин ± 2 с; итог показывает разности по каждой игре; прерванная серия не даёт разностей (как в `series-core.test.ts`).

**Чего не делать.** Не рандомизировать порядок игр между фазами — набор в flow строго тот же, что в detail, иначе разность грязная. Не крутить сложность долей подсказок — только фазой (правило series.ts).

## 2. Претест первым шагом серии + ползунок уверенности (принципы 16 и 15)

**Зачем.**
- Претест (Richland 2009, Latimier 2019): попытка ответить ДО материала создаёт «слот»; при встрече с ответом срабатывает prediction error и кодирование сильнее на 10–20 %. Сейчас серии начинаются с показа, слота нет.
- Уверенность (Flavell 1979, Dunlosky 2013): главный враг обучения — fluency illusion, «казалось, что знаю». Если перед ответом человек ставит уверенность, а потом отвечает, за неделю виден график калибровки: где переоценивает себя. Такой метрики нет ни у одного массового тренажёра, это наш отличительный признак.

**Как устроено — два метапараметра серии, включаются флагом на игру.**
- `pretest: true` → перед первым блоком серии один вопрос по материалу, который ещё не показан: в vocab_srs — «как переводится…» до карточки; в chess_blind/scholars-mate — «где будет мат?» до подсветки; в memory_palace — «какой предмет на месте 3?» до маршрута. Ответ не оценивается баллами и не влияет на уровень; он пишется в сессию как `pretest_correct: bool`. Затем серия идёт как обычно.
- `confidence: true` → перед вводом ответа ползунок или три кнопки: «уверен / скорее да / наугад» (значения 0.9 / 0.6 / 0.3). Ввод ответа доступен после выбора. Пишется парой `(confidence, correct)`.
- Экран статистики: калибровочная кривая — по трём корзинам уверенности фактическая доля верных; **переоценка** = средняя уверенность минус средняя точность. Для человека одна фраза: «Когда ты уверен на 90 %, ты прав в 61 %».

**За что цепляться.** `services/series.ts`: в `SeriesRun` добавить `pretest?: { asked: string; answer: string; correct: boolean }` и в `SeriesBlock` массив `confidence?: number[]` параллельно ответам; `seriesSession()` кладёт оба в запись. Флаги — в реестре `constants/games.ts` у игры (`meta: { pretest, confidence }`), чтобы гейт читал данные, а не надписи. Ползунок — один общий компонент, подключается в экранах ответа (`TypingAnswer.tsx` у vocab_srs — первый кандидат).

**Метрика.** `overconfidence = mean(confidence) − mean(correct)` за 7 дней; `pretest_gain` = точность после серии у позиций с претестом против без (A/B внутри одного человека: чётные серии с претестом, нечётные без, первые две недели).

**Приёмка.** Претест никогда не меняет уровень и баллы (проба); без выбора уверенности ответ ввести нельзя; в `sessionHistory` у сессии есть оба поля; экран статистики строит кривую при ≥ 30 ответах, до этого пишет «мало данных», а не рисует шум.

**Чего не делать.** Не показывать правильный ответ претеста сразу — он придёт в самой серии, в этом суть. Не делать уверенность обязательной для Алекса (детский профиль — выкл по умолчанию).

## 3. Ночной цикл: «слепой прогон» 21:15 → разбор 07:00 + звуковой якорь (принципы 9, 17; Zhang 2025, Hu 2020)

**Зачем.** Zhang et al. 2025 (npj Science of Learning, N=48): retrieval practice **без обратной связи** консолидируется во сне — группа с сном забывала значимо меньше, удержание коррелировало с плотностью быстрых веретён (r = 0,52). Zheng 2023: на новом материале recall без ответа может вредить, поэтому обратная связь обязана прийти, но утром. Отсюда пара: вечером карточки без ответов, утром те же с ответами. Ночь становится частью упражнения бесплатно.
TMR (Hu 2020, мета 91 эксперимент, g = 0,29): сенсорный якорь при обучении и он же во сне усиливает консолидацию. Гаджеты стимуляции сна не работают (Jourde 2026), поэтому только дёшево: один звук на тему днём в наушниках, напоминание про запах у подушки вечером. Мы не воспроизводим звук во сне (нет доказанных домашних средств), мы делаем якорение днём и подсказку.

**Как устроено.**
- Вечерний слот (`warmup.ts` уже знает `slotForHour` → `'evening' | 'night'`): в 21:15 уведомление «5 минут карточек перед сном». Открывается **слепой прогон** vocab_srs: карточки из очереди `buildQueue`, ответ вводится, но **правильный ответ не показывается**, оценка не ставится, `gradeCard` не вызывается. Пишется черновик `pending_review: [{cardId, answer, ts}]` в AsyncStorage рядом с `psygames_vocab_srs_<base>_<target>`.
- Утренний слот 07:00: уведомление «разбор вчерашнего». Те же карточки в том же порядке, показывается вчерашний ответ и правильный, человек видит расхождение, **здесь** вызывается `gradeCard` с автооценкой (wrong → again, correct → good, как сейчас). Экран показывает «за ночь удержано N из M».
- Если утренний разбор не открыт до 12:00 — черновик сгорает, карточки возвращаются в очередь без штрафа (сон был, разбора нет — не наказывать).
- Звуковой якорь: у темы (языковая пара или колода) один трек из `services/music.ts` (`TRACKS`, `startMusic(preferId)`), закреплённый за темой в настройках; он играет только в учебных сессиях этой темы. Вечернее уведомление добавляет строку «запах у подушки — тот же, что утром» для тех, кто включил TMR в настройках (по умолчанию выкл).

**За что цепляться.** `services/reminders.ts` уже даёт локальные daily-уведомления с `data.type: 'morning' | 'evening'` и обработчиком тапа в `app/_layout.tsx`; добавить типы `'srs_blind'` (21:15) и `'srs_review'` (07:00), времена — из настроек. ⚠️ На web/Tauri уведомления no-op (Platform guard) — там вместо пуша бейдж на карточке колоды «вечерний прогон ждёт» по `currentSlot()`. `services/vocab-srs.ts`: новый экспорт `blindPass(queue)` → черновик, `reviewPass(draft)` → вызовы `gradeCard`. Музыка: поле `anchorTrackId` в настройках колоды.

**Метрика.** `overnight_retention = верных утром / всего в черновике`, отдельно для карточек, которые вечером были отвечены верно и неверно. Сравнение с дневными сессиями той же колоды за ту же неделю — это и есть проверка Zhang на своих данных.

**Приёмка.** Проба: вечерний прогон не вызывает `gradeCard` ни разу; утренний разбор вызывает ровно по числу карточек черновика; черновик старше 12:00 удаляется без изменения `CardState`; уведомления на native приходят в заданное время (ручная проверка на Android-сборке), на web бейдж появляется после 21:00.

**Чего не делать.** Не воспроизводить звук ночью и не обещать «стимуляцию сна» — доказательств для домашних устройств нет (Jourde 2026), в тексте приложения слово «стимуляция» не употреблять. Не давать слепой прогон на новых карточках (ни разу не показанных): Zheng 2023 — на новом материале без ответа возможен отрицательный эффект; в вечернюю очередь идут только карточки с ≥ 1 повтором.

## Порядок и оценка

1. Режим 1 — 1 день (флаги в плейлисте и паузе, экран разности).
2. Режим 2 — 1,5 дня (поля в series.ts, компонент уверенности, экран калибровки).
3. Режим 3 — 2 дня (черновик, две ручки vocab-srs, два типа уведомлений, бейдж на web).

Сдача каждого — строкой в канал psygames со скриншотом и выводом пробы. Метрики трёх режимов через две недели использования — в один отчёт: отношение скоростей фаз, переоценка уверенности, ночное удержание.
