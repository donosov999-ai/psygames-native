# Снимки карточки Google Play

Снято скриптом `frontend/scripts/store-shots.mjs` с живой веб-сборки.
Сторожит набор гейт `frontend/src/__tests__/store-shots.test.ts`.

## Что здесь лежит

`ru/` — десять кадров 1080×1920 и манифест `shots.json`.

| кадр | что показывает | в карточку |
|---|---|---|
| 01-catalog | сетка упражнений (прокручена до игр) | да |
| 02-dots-connect | поле «Соедини точки» | да |
| 03-one-line | поле «Одна линия» | да |
| 04-faces-names | поле «Лица и имена» | да |
| 05-object-tracker | поле «Слежение за объектами» | да |
| 06-navigator | поле «Навигатор», фаза ответа | да |
| 07-rhythm-pitch | задание «Ритм и высота» | нет |
| 08-memory-palace | поле «Дворец памяти», размещение | да |
| 09-levels | тропинка уровней (1/40) | да |
| 10-statistics | экран статистики | нет |

**Помечено для карточки 8** — это потолок Google Play на тип устройства.
Остальные два лежат как библиотека: набор пересобирают, не переснимая.

## Требования Play, по которым всё сверяется

Проверено по [support.google.com/googleplay/android-developer/answer/9866151](https://support.google.com/googleplay/android-developer/answer/9866151)
19.08.2026 — требования менялись, поэтому сверено, а не по памяти.

- JPEG или **24-битный PNG без альфа-канала**, до 8 МБ на файл;
- сторона от 320 до 3840 px, длинная сторона не больше двух коротких;
- **от 2 до 8 снимков на тип устройства** (телефон считается отдельно от планшетов);
- для крупных промо-блоков магазина нужен портрет 9:16 от 1080×1920.

Отсюда кадр 1080×1920: viewport 432×768 при deviceScaleFactor 2.5 даёт его ровно,
без передискретизации. Растягивать снимок ради круглого числа нечестно — человек
поставит приложение и увидит другое.

## Пересъёмка

```bash
cd ~/dev/psygames/frontend

# 1. Сборка. baseUrl="" ОБЯЗАТЕЛЕН: со штатным "/psygames-web" шрифты и ассеты
#    дают 404, кнопки молча не срабатывают, и снимок уезжает с полупустым экраном.
cp app.json app.json.bak \
  && sed -i '' 's|"baseUrl": "/psygames-web"|"baseUrl": ""|' app.json \
  && npx expo export -p web --output-dir dist-shots; mv app.json.bak app.json

# 2. Поднять статику
npx serve dist-shots -l tcp://127.0.0.1:8195

# 3. Снять (в другом окне)
node scripts/store-shots.mjs --base=http://127.0.0.1:8195
node scripts/store-shots.mjs --base=http://127.0.0.1:8195 --only=06-navigator   # точечно

# 4. Проверить
npx jest src/__tests__/store-shots.test.ts
```

⚠️ Не собирать веб одновременно с правкой исходников: соберётся недописанное
дерево, и снимки будут врать про состояние приложения.

## Три вещи, на которых этот набор уже обжигался

**1. По маршруту `/games/<id>` открывается экран настройки, а не игра.** Карта
уровней и кнопка «Начать» выглядят на снимке ровно так же прилично, как поле:
заголовок, градиент, кнопки. Подмена не выглядит как ошибка — она выглядит как
скриншот. Поэтому скрипт заходит в игру (`?auto=1` плюс один клик по кнопке
внутри партии) и проверяет **маркер поля** — текст, который есть только в партии.
Не нашёл — кадр не сохраняется, прогон краснеет.

**2. Профиль по умолчанию — «Стандарт», девять упражнений.** Каталог с девятью
карточками противоречит тексту карточки магазина. Скрипт ставит профиль владельца
`odv999` и проверяет, что тот применился, по числу карточек в каталоге (77 против
24) — а не «на веру».

**3. Якорей каркаса `GameShell` у новых игр нет.** `game-toolbar` /
`game-header-actions` есть у 62 игр из 71, но шесть из семи новых нарисованы
своим каркасом. Гейт, построенный только на них, краснел бы на исправных играх, а
ложное срабатывание хуже отсутствия проверки. Якоря записываются в манифест как
есть; доказательством поля служит маркер текста плюс sha256 файла.

## Долги

- **Только русский.** Маркеры поля выписаны для `ru`; на другом языке скрипт
  откажется снимать, а не снимет вслепую. Английский набор с полосами заголовков
  лежит отдельно — `store/google-play/assets/screenshots/en/` (снят
  `scripts/play-screenshots.mjs`, другой подход: композиция с крупной подписью).
- **Статистика в карточку не идёт.** На чистом профиле экран пустой («0 игр»,
  «Сыграйте несколько игр, чтобы увидеть статистику»), половина кадра — пустота.
  Наполнить его можно только историей тренировок: выдумывать её для магазина —
  враньё, а играть неделями ради снимка скрипт не может. Решение за владельцем:
  снять с боевого профиля с историей либо оставить вне карточки.
- **`dots-connect` и `one-line` снимаются на тренировочной сетке.** Путь
  rules → training → playing зашит в модулях, пропуск включается только со второго
  захода, после пройденного уровня. Это ровно то поле, которое видит человек в
  первую минуту после установки, но боевая сетка крупнее и интереснее.
- **Бейдж справки «Прав…» обрезан** в правом верхнем углу игровых экранов и на
  `object-tracker` наезжает на «Выйти». Это состояние приложения, а не съёмки —
  чинится в UI, не здесь.
