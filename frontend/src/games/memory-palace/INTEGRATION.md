## 1. Каталог — `src/constants/games.ts`

Вставить в блок `category: 'memory'`, рядом с `mnemonics`:

```ts
  {
    id: 'memory_palace',
    nameKey: 'memoryPalace',
    descKey: 'memoryPalaceDesc',
    skillKey: 'skillSequence',
    gradient: ['#8b5cf6', '#0f766e'],
    icon: 'map',
    route: '/games/memory-palace',
    category: 'memory',
  },
```

- `id` обязан быть `memory_palace`: этим ключом уже пишутся уровень
  (`psygames_memory_palace_level_<профиль>`), звёзды, незаконченная партия и `game_type`
  в истории сессий. Меняешь id — теряется весь прогресс.
- Градиент `#8b5cf6 → #0f766e` — из хендофа модуля, и он уже посчитан:
  `onGradientText` даёт по нему вуаль (сплошным цветом AA 4.5 недостижим, белый берёт
  только 4.23 на фиолетовом конце), поэтому плашки на экране нарисованы через
  `GradientSurface`. Поменяешь градиент — пересчитать обе плашки.
- `skillKey: 'skillSequence'` — тот же, что у «Мнемоники»: обе про память на
  последовательность. Различие между ними — не в навыке, а в опоре (см. §6).
- Иконка `map` — из Ionicons. Своей картинки в `gameIcons.ts` нет и не требуется:
  `GameCard` сам откатывается на Ionicons. Захотите картинку — файл кладётся в
  `assets/images/game_icons/memory_palace.webp` и строчка в `GAME_ICONS`.

## 5. Профили — `src/constants/profiles.ts`

Где `allowed_games: 'all'` (`odv999`, `nzt48`) игра появится сама.

Дописать `'memory_palace'` в белые списки:

| Профиль | Зачем именно там |
| --- | --- |
| `students` | метод мест — это учебная техника в чистом виде: списки, определения, порядок пунктов. Ближайший практический перенос из всего каталога. |
| `seniors` | нагрузка растёт содержанием, а не скоростью: таймера в игре нет вовсе, а первый уровень — пять мест. Игр без спешки в наборе мало. |
| `execs` | удержание повестки и порядка пунктов без записи; партия делится на короткие фазы, её можно прервать и вернуться — партия переживает выход. |

Куда НЕ добавлять и почему:

- `kids` (7–12) — партия на минуты с фазой «оживите ассоциации» требует произвольного
  усилия, которого в этом возрасте ещё нет; ребёнок бросит на расстановке.
- `free` (Стандарт) — в описании профиля число игр вбито строкой и сверяется гейтом
  `game-standard`; добавлять туда игру можно только вместе с правкой подписи на 12 языках.
- `chess`, `vasilyeva`, `drivers`, `women`, `polyglot` — наборы собраны под другие
  подсистемы, память на последовательность там уже закрыта «Мнемоникой» и объёмом.

## 6. Зарядка (`warmup_playlist` в профилях) — ДА, но только в утренний/дневной набор

```ts
    { game_id: 'memory_palace', game_route: '/games/memory-palace', difficulty: 'easy',
      settings: { level: 3 }, est_duration_sec: 180 },
```

- `level: 3` — шесть мест и два лишних предмета. Это примерно три минуты: маршрут,
  расстановка, запоминание и два прохода проверки. Ниже брать бессмысленно (пять мест
  человек держит и без всякого метода), выше — шаг зарядки распухает за четыре минуты.
- Шаг зарядки уровень НЕ двигает (`isPreset` → без `lvl.reach`), это уже в экране.
- ⚠️ В ВЕЧЕРНИЙ И НОЧНОЙ набор не ставить. Игра требует произвольного усилия на
  «оживите ассоциации» — это ровно противоположно задаче вечернего набора. Технически
  запрета нет: `useCalmHush(isCalm)` подключён, звук приглушится, но смысл шага испортится.

## 7. Проверить после внесения

```
npx jest src/__tests__/game-routes.test.ts src/__tests__/game-standard.test.ts \
         src/__tests__/i18n-coverage.test.ts src/__tests__/help-map.test.ts \
         src/__tests__/memory-palace-integration.test.ts
```

`game-standard` увидит экран только ПОСЛЕ записи в каталог — до неё он его не проверяет
(берёт маршруты из `GAMES`). Все три его требования экран уже выполняет:
`usePersistentLevel('memory_palace')`, `<LevelProgressMap>` на экране настройки,
`<LevelCleared>` как единственный итог, и `level: doneLevel` в `saveSession`.
